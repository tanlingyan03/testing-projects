数据不一致问题汇总（3处）

ISSUE-001 | 严重程度：高

创建订单接口：订单总金额存在精度误差（相差0.01元）

涉及接口
POST /user/order
问题描述
调用创建订单接口后，接口返回的 totalAmount 与数据库中存储的订单总金额存在 0.01 元的精度偏差。经排查，问题源于后端在计算订单金额时使用了浮点数运算，导致精度丢失。
请求参数
{"cartItemIds":[1],"addressId":1,"remark":"请尽快发货"}
接口响应
{"code":0,"data":{"id":15,"orderNo":"202412150001","totalAmount":199.98}}
数据库断言
SELECT total_amount FROM `order` WHERE id = 15;
-- 查询结果: 199.97
预期结果
total_amount 应为 199.98（商品价格 99.99 × 数量 2 = 199.98）
实际结果
数据库中存储为 199.97，接口返回为 199.98，两者相差 0.01
根因分析
后端使用 double 类型进行金额计算，浮点数运算导致精度丢失。建议将金额字段统一改为 Decimal(10,2) 类型进行精确计算。
修复建议
1. 数据库金额字段使用 DECIMAL(10,2)；2. 后端使用 BigDecimal 进行金额计算；3. 在单元测试中增加精度校验。
ISSUE-002 | 严重程度：高

获取订单详情接口：订单项数量与数据库记录不一致

涉及接口
GET /user/order/{id}
问题描述
创建订单时传入包含2个购物车项的 cartItemIds，但获取订单详情时，接口返回的 items 数组仅包含1个订单项，与数据库中实际存储的订单项数量不一致。
请求参数
{"cartItemIds":[1,2],"addressId":1,"remark":""}
接口响应
{"code":0,"data":{"id":16,"items":[{"productId":1,"quantity":2}]}}
数据库断言
SELECT COUNT(*) as item_count FROM order_item WHERE order_id = 16;
-- 查询结果: 2
预期结果
items 数组长度应为 2，与 cartItemIds 传入数量一致
实际结果
接口返回 items 长度为 1，但数据库中 order_item 表有 2 条记录
根因分析
订单详情接口在查询订单项时可能使用了错误的 JOIN 条件或存在 LIMIT 限制，导致仅返回部分数据。也可能是接口层对订单项进行了错误过滤。
修复建议
1. 检查订单详情查询 SQL 是否存在 LIMIT 1；2. 确认 JOIN 条件是否正确；3. 检查接口层是否对 items 数组进行了错误截取。
ISSUE-003 | 严重程度：中

获取管理员信息接口：角色字段返回 null

涉及接口
GET /admin/info
问题描述
管理员登录成功后，调用获取管理员信息接口，响应中 role 字段返回 null，但数据库中该管理员账号的 role 字段值为 "admin"。
接口响应
{"code":0,"data":{"id":1,"username":"admin","role":null}}
数据库断言
SELECT role FROM admin_user WHERE username = 'admin';
-- 查询结果: 'admin'
预期结果
接口返回 role 应为 "admin"
实际结果
接口返回 role 为 null，与数据库值不一致
根因分析
后端实体类与数据库表字段映射可能存在字段名不一致问题（如数据库字段名为 role，但实体类属性为 roleName），导致 ORM 映射时 role 字段未被正确赋值。
修复建议
1. 检查 AdminUser 实体类属性名与数据库字段名是否一致；2. 检查是否使用了正确的 @Column 注解映射；3. 确保查询 SQL 中包含了 role 字段。

MySQL 数据库断言方法说明

断言类型 典型SQL示例 验证目的
